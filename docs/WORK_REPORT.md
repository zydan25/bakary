## ملخص الحالة

تم تأسيس مستودع المشروع بوثائق المتطلبات وقواعد العمل وهيكل أولي للتطبيق. توجد إعدادات Flask Application Factory، وإضافات SQLAlchemy وFlask-Migrate وFlask-Login وCSRF، وواجهات تسجيل الدخول ولوحة التحكم، ونظام أولي للأدوار والصلاحيات، وإعداد PM2/Gunicorn على المنفذ 4043 وملف Manifest للـ PWA.

**حالة التحقق الحالية:** اجتاز GitHub Actions التشغيل رقم [78](https://github.com/zydan25/bakary/actions/runs/38582888674) بنجاح على Python 3.10 و3.12؛ ويشمل تشغيل `flask db upgrade` على قاعدة PostgreSQL فارغة ثم الاختبارات. لا يعني هذا أن التطبيق جُرّب يدويًا في المتصفح أو أن PostgreSQL المحلي وPM2 وPWA قد تم التحقق منها على خادم فعلي؛ لذلك لا يُعلن بعد جاهزًا للإنتاج.

## ما تمت مراجعته في المستودعات المرجعية

- `water-pos-postgres`: `README.md`، و`templates/base.html`، و`static/css/style.css`. تم اعتماد اتجاه RTL، وخلفية فاتحة، وبطاقات بيضاء وحدود خفيفة، والأزرق `#1a56db`، والتنقل المناسب للهاتف.
- `alattabbot`: `app.py` و`models.py` و`requirements.txt`. تم الاستفادة من نمط كائن SQLAlchemy المشترك وFlask-Migrate، مع تجنب تجميع كل المسارات داخل ملف واحد.
- `bakary`: تمت مراجعة إعداد التطبيق والموديلات والمصادقة والصلاحيات والقوالب وإعداد PM2 وملف Manifest وسير عمل الاختبارات.

## قواعد الجودة التي لن نتجاوزها

1. لا يُعدل رصيد الحساب أو المخزون يدويًا بدل قيد حركة يمكن تتبعه.
2. لا يُحذف سجل مالي مسجل؛ التصحيح يكون بعكس/تسوية بصلاحية وسبب.
3. تُحسب الأموال في الخادم باستخدام `Decimal/NUMERIC`، لا باستخدام حسابات المتصفح وحدها.
4. لا يُعلن حفظ العملية قبل نجاح الخادم، ويُمنع الإرسال المكرر.
5. كل عملية إقفال قابلة للتدقيق، ولها مفتاح يمنع إقفال الفترة نفسها مرتين.
6. لا تُرفع كلمات مرور أو مفاتيح سرية إلى Git.
7. لا يبدأ الانتقال إلى مرحلة جديدة قبل مراجعة ملفات المرحلة واختبارها وتحديث هذه الوثيقة.
